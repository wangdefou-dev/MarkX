# MarkX

一个面向 Apple Silicon Mac 的原生 X 长文归档工具。当前版本为 `0.3.47`（Build 134），三栏资料库布局以 0.3.0 为基线。

## 0.3.47 更新

- 隐藏侧边栏后，“全部文章”等分类标题靠文章列表右侧对齐，随列表位置与宽度更新，左上角产品名和侧栏开关保持固定。

## 0.3.46 更新

- 外层界面字号较 0.3.45 回调 1pt，正文维持 15pt 基础字号及已有阅读缩放。
- 标题、作者、标签和正文共用居中的 860pt 阅读栏，增加头部间距，删除正文顶部的排版校验提示与重复统计。
- 左上角仅保留一个较大的圆形侧边栏开关，隐藏侧栏后仍可直接恢复。

## 0.3.45 更新

- 应用界面和正文基础字号统一增加 2pt，覆盖侧栏、文章列表、设置、弹窗与进度页；正文缩放比例保留并作用于新的基础字号。
- 收紧详情页标题、作者、标签与排版校验提示的间距，取消标题固定高度，窄窗口下元数据与标签自动换行。

## 0.3.44 更新

- 侧边栏开关固定在左上角 MarkX 名称旁，隐藏侧边栏后仍可直接点击显示，不会进入工具栏溢出菜单。
- 点击文章或切换分类时保留侧边栏显隐状态，不再自动展开三栏。

## 0.3.43 更新

- 资料库与博主分类标题从 12pt 调整为 14pt 半粗，改用主文字颜色，浅色模式为黑色，深色模式自动适配。
- 侧栏“开始下载文章”从 13pt 调整为 15pt，保留橙色和原有按钮布局。

## 0.3.42 更新

- 资料库与博主分组的折叠箭头向内收 16px，展开与收起保持同一对齐位置。
- 删除侧栏左下角的保存文件夹入口，目录选择统一从设置页进入；空闲时侧栏底部不再保留独立模块。

## 0.3.41 更新

- 浏览器登录检测覆盖 Chrome、Edge、Brave、Arc、Vivaldi、Opera、Chromium、Chrome Canary、夸克、豆包与 Firefox；自动检查多个配置与两种 Cookie 路径，不再只依赖 Chrome 的最后使用配置。
- 检测只读取 X 登录记录元数据，实际导入才读取对应钥匙串并在内存中解密；过期或不完整的会话不标记就绪，不合并不同浏览器或 Firefox 容器的账号。
- 区分未发现登录、数据读取受限、钥匙串与解密失败；设置中可选择浏览器、验证会话读取，或为自定义数据目录保存访问授权，无需重新登录 X。Safari 暂不支持自动导入。
- 浏览器和存储连接状态统一收进设置菜单，左下角仅保留归档目录与运行中的任务摘要。
- 橙色背景仅覆盖下载按钮，不再延伸到窗口控制区；原生窗口控制按钮右侧显示 MarkX 产品名。
- 中间列表与右侧阅读区共用窗口工具栏底部分界线；文章标题、作者与状态随正文滚动，取消阅读区内部的独立头部分割线。

- 下载、连接配置、即时/定时同步与结果窗口统一标题、分组表单、可滚动内容和固定操作底栏；长表单不会挤走主按钮。

## 0.3.37 更新

- 刷新失败和重复重试始终保留原 Markdown 路径，每次替换前检查手工修改；没有数据库路径的同名文件也受保护。
- 安全停止会取消并等待全部后台保存和 uPic 上传子进程，停止结束前禁止启动新任务或迁移资料库。
- 图床回读验证非空内容、文件头、返回长度和 Range 范围；服务器忽略 Range 时也只读取最多 4096 字节。
- 全量扫描按“无新增内容”的轮询次数限时，持续增长的历史不再受 320 次总轮询限制；部分扫描和失败扫描不会报告全部完成或更新线上总数。
- 文章列表新增中文全文搜索，覆盖标题、博主和正文，支持一两个汉字；历史文章在后台补齐索引，搜索沿用当前侧边栏分类。
- 正文 JSON 和 Markdown 异步加载，本地图片使用有界缩略图缓存，切换文章时取消过时的加载结果。
- 新媒体缓存与本地备份优先通过硬链接共享文件内容；“资料库 → 整理重复媒体缓存…”会在确认后逐字节核对，仅移除已有相同备份的隐藏副本，旧快照自动回退到备份。

## 已实现

- SwiftUI 原生三栏资料库界面；
- X 黑白配色、四周留有安全边距的完整 X 标志，三条文章横线位于 X 左上斜臂的黑色内镂空中，包含完整 macOS `.icns` 尺寸；
- 首次配置与本地归档目录；
- 自动复用受支持本机浏览器的 X 登录态；应用不再提供 X Developer API 配置或 Bearer Token 输入，也不读取旧版 API Token；
- 单个博主主页下载和多账号批量输入；
- 支持一次粘贴 1–500 条 X Article `status` 或 `article` 链接，按输入顺序在应用内打开 X 页面并采集；
- 「单个博主」的博主主页输入框严格限制为一行：回车不换行，粘贴多行内容时只保留第一条非空内容；批量博主和文章链接仍使用多行输入；
- 在默认“单个博主”页直接粘贴 `/status/` 或 `/article/` 文章链接时，会自动切换为文章直链模式，不会误将用户名当成博主后扫描 300 条 Post；
- 侧边栏和工具栏使用统一的“开始下载文章”入口，在同一窗口选择单个博主、批量博主或文章链接；左上角入口、资料库/博主列表与左下角状态卡共用同一左右边距，下载入口与资料库、资料库与博主之间留有更明确的间距；左上角入口使用橙黄色半透明矩形背景，左下角状态卡保持原来的材质底；
- 左侧资料库的“全部文章”“今日推文”“商单内容”“等待继续”“需要处理”始终显示与当前筛选结果一致的数字；“今日推文”按 X 原始发布时间动态筛选当天发布的文章，并在跨日后自动更新；“商单内容”只列出带有 X 官方 Paid partnership 付费合作标记的文章，文章列表和详情页同步显示“商单内容”标签；“等待继续”表示历史未完成记录，不再冒充当前正在运行的任务；每个博主行使用“已下载 / 线上总数”分数显示，左侧只统计已完成下载的文章，右侧显示最近一次完整扫描确认的线上 Article 总数；尚未完整扫描时右侧显示 `?`；
- 博主行只负责选择和显示统计，不常驻任何功能按钮；查看主页、重新拉取和删除都从该行右键菜单选择。“全部文章”“等待继续”“需要处理”的相关操作也集中到各自右键菜单；
- 博主发现直接打开 `https://x.com/<handle>/articles`，只滚动 Article 专属列表并收集精确 `/status/PostID` 和 `/article/PostID` 链接，不扫描博主普通 Post；一位博主的列表读完后立刻开始保存正文，同时继续读取下一位博主的列表。正文采集在页面排版稳定后立即开始下一篇，图片和视频在后台保存，不互相等待；只有结构完整且连续一致的快照才会进入归档，Markdown 校验仍然在写入前执行。大批量任务只保留 2 个隐藏网页，并定期换新浏览器进程；内存里只排一小段下载队列，其余待办写在 SQLite，进度列表只显示当前窗口。页面 JSON 解析和进度刷新不堵主线程，任务结束后也不会为修路径把整个资料库扫一遍导致“没有响应”；
- 博主发现、直接链接下载、已有文章重新获取和完整正文保存全部为 **0 次 X API 请求**；只有本地 Markdown 和来源快照都还在的文章才会跳过。新设备上资料库有记录但正文文件不在时，会重新加入下载队列并真正保存，不会只刷新数字；
- 最近文章数量可选（1–100 篇），默认每位博主最近 10 篇；也可直接选择“全部文章”，滚动到 Articles 列表底部下载全部可见文章，不受 100 篇限制；
- “开始下载文章”支持“最近范围”和“全部文章”两种模式，快捷选择里也可一键切到全部文章；
- 博主列表支持最多置顶 5 位，置顶项可通过拖拽或右键上移/下移调整顺序，顺序保存在本机设置中；侧边栏不再单独显示置顶分组标题、图钉图标或 `N/5` 数量，置顶博主仍排在列表最前，行内保留橙色图钉标记；
- 选择“完整历史”时自动滚动 Articles 专属列表直至底部，不调用 Full-Archive Search；
- 右上角“立即同步”是独立批量功能：点击后先弹窗确认每位博主要检查的最近 1–100 篇（默认 10 篇）或全部文章，确认后后台逐位扫描 Articles 列表，再按选定范围同步全部已跟踪博主；博主总数不设上限，100 位或更多也会全部进入队列；
- “同步所有博主文章”弹窗重新统一了工具栏与弹窗的同步图标、标题字号、正文字号、图标容器和卡片间距；“立即同步”和“定时同步”通过顶部分段选择分开；
- 支持每日定时后台同步：可选时间和每位博主文章数，保存后注册用户级 macOS LaunchAgent；应用窗口关闭时也能隐藏唤起，睡眠错过后会在下次唤醒时补执行一次，完全关机时无法执行；
- 定时同步会持久保存最近执行时间与结果；上一个任务仍在运行时安全跳过本次，不会并发写入同一资料库；
- 批量同步会自动跳过已经通过完整性校验的本地归档，只让新文章和未完成文章进入正文队列；过程显示检查、保存、跳过、失败与图片/视频数量，结束后显示独立同步结果；
- 输入博主主页后使用纯原生后台进度窗口：逐条显示从 Articles 专属列表识别到的文章标题与精确链接，不展示 X 浏览器页面；
- 同一时刻只保留一个资料库主窗口：菜单不再提供「新建窗口」，定时同步 URL 和应用恢复都回到已有窗口，不会再叠出第二份主界面；下载进度窗口也不会因窗口恢复而重复出现；
- 发现和正文下载的进度窗口每次打开都以主软件窗口为锚点居中；可点击「隐藏到后台」或红色关闭按钮收起，不会取消 WebKit 页面、当前文章或后续队列；任务运行期间可从主窗口工具栏「显示下载进度」重新打开，并按主窗口最新位置再次居中；
- 正文下载阶段继续隐藏浏览器，只显示每篇文章的等待、下载中、已保存或失败状态；全部结束后用固定尺寸结果弹窗报告成功、跳过、失败和图片/视频数量，每项为小图标、标签和数字紧挨排列，长说明在弹窗内滚动，不会撑破窗口；
- 订阅用户专享文章会从 X 页面可见文案与订阅链接联合识别为独立的“需要订阅”状态，立即停止该篇的无效加载重试，但永久保留任务；原文与订阅页会使用设置中选定的浏览器打开，订阅或切换到已有权限的账号后可一键重新处理；应用不会尝试绕过 X 的订阅权限；
- 精确采集可随时停止，停止后不再自动进入下一篇，未完成任务保留并可从侧边栏继续；
- 文章级停止、失败与重新开始状态会持久化：详情页显示明确错误原因和最近 30 条处理日志，应用重启后仍可查看；当前文章可从文章行或状态卡右键停止，失败或停止后可重新处理；
- 队列只能在每篇文章得到“已保存”“明确失败”或“用户停止”结果后前进；结束时还会核对资料库剩余任务，只要仍有等待继续或需要处理的文章，就只报告“本次队列结束，仍有未完成文章”，不会误报全部处理完成；
- “需要处理”的右键菜单支持重新处理失败任务或清空任务；已经确认需要订阅才能访问的文章会直接跳过并提示数量，不会再次打开页面。文章行右键菜单支持重新处理单篇和删除单条任务，单篇重新处理仍会打开该文（方便订阅后再试）。删除前必须确认；已有 Markdown、全文快照和图片归档保留，只删除未归档临时记录或取消后续重试；
- 所有按钮、图标按钮、菜单入口和分段选择器都提供鼠标悬停说明，提示会执行的动作及删除边界；
- 任务进度明确显示 `X API 0`、已发现文章、已保存文章和已保存图片/视频；
- “全部文章”按发布时间平铺展示，不再按作者分段；文章列表每行显示当前列表序号；归档根目录的可见内容固定为 `Blogger/` 与 `media/`，所有具体博主目录统一位于 `Blogger/`，总索引为 `Blogger/index.md`；旧版根目录博主文件夹会在校验无冲突后自动迁移并更新数据库绝对路径；
- 文章支持右键删除并在确认后移入 macOS 废纸篓，同时清理数据库记录、来源快照和索引；远程图床文件不会被误删；
- 已存在的博主可从侧边栏反复“重新拉取文章”，每次都能重新选择 1–100 篇或全部文章；
- 博主行保持简洁，不显示刷新和删除图标；右键菜单保留查看主页、重新拉取和删除博主。删除只停止跟踪，已下载文章、本地媒体缓存和远程图片/视频都会保留，再次添加即可恢复拉取；
- 选中博主后，窗口最顶部的导航区只保留一行“博主名称 + 查看主页”，按钮紧跟博主名称右侧；文章列表只保留文章卡片；
- 最近范围和完整历史模式；
- 严格只识别带官方 `article` 字段的 X Article；Note Post、普通 Post 和自回复线程不计数、不下载；
- 内置不可见的非持久化 X Article 页面运行时，仅从 `twitterArticleReadView` / `longformRichTextComponent` 读取已渲染的文章块；采集时不会把 X 页面界面展示给用户；
- 每篇文章自动读取已检测到的本机浏览器 X 会话，等待页面排版连续稳定后自动保存，不要求重复输入 X 密码或手动点击保存；
- 浏览器会话只在本机内存中用于当前后台采集，仅解密 `x.com` / `twitter.com` 必需 Cookie，不读取其他网站，不打印、不落盘、不上传给开发者；读取受限时在设置中授权数据目录，失败原因会收进最终结果；
- 按 X 页面原始顺序采集封面、标题层级、段落、有序/无序列表、引用、表格、粗体/斜体/删除线/下划线、链接、代码块和内文图片；未知块出现时拒绝导出，不猜测位置；
- 正文中的“引用其他 X Article”卡片在原位置简化为唯一的引用文章链接；已删除或失效的引用内容保留页面占位说明，不再被误判为未知排版块；不会把卡片作者、日期、摘要和互动数据误当正文，也不会误存作者主页；
- “本地 + uPic”模式先把每张图片和 MP4 按 SHA-256 保存并校验到 `media/`，再调用 uPic 上传；Markdown 默认使用 uPic 返回的 HTTPS 链接，本地文件作为备份和应用内预览来源；应用不读取、复制或记录 uPic 容器中的图床配置与密钥；
- uPic 子进程最长等待 5 分钟；超时会自动终止该次上传、保留当前文章任务并继续后续队列，不会无限阻塞整次同步；
- 只把 `pbs.twimg.com/media/` 下的真实 Article 媒体视为正文图片，排除头像、emoji 和页面图标；四图等轮播块会逐张按页面顺序采集并去重，保存前校验所有图片已加载且媒体 ID 集合齐全；
- X 原图下载、S3/R2 上传和上传后公网回读均有有界自动重试；同一篇文章反复失败只计为 1 篇，成功后自动清除失败状态；
- 兼容 X Article 正文内视频：从页面媒体元数据选择最高分辨率渐进式 MP4，排除 `blob:`、HLS、音轨和初始化分片；
- MP4 下载后校验 MIME、文件头、大小与 SHA-256，默认保存到归档目录 `media/videos/`；选择 uPic 时本地与图床同时保存并回读验证，选择 S3/R2 时继续使用原有远程存储路径；
- 视频保留原文块顺序：Markdown 输出 HTML5 `<video controls>` 和备用下载链接，App 详情页用 AppKit `AVPlayerView` 直接播放已验证 MP4；解析、下载、上传或回读失败时不伪装完成；
- 音频、直播、只有 HLS 的媒体和外站 iframe 暂不在本次视频兼容范围内；
- 忽略 X DraftJS 遗留的零高度空原子节点：只有节点同时无子元素、无文字、无媒体身份且不占据任何页面高度时才安全跳过；真实未知块和仍占位的懒加载内容继续严格拒绝，避免把残缺正文误标为完成；
- 兼容 X 把整篇文章渲染成一个超长 DraftJS 正文块的合法页面；单块文章会使用更长的内容稳定等待窗口，确认连续多次完全一致后才保存；
- 右侧以文章阅读版式展示已校验的完整正文、富文本样式、代码和全部图片，并提供 80%–160% 的文字缩小、恢复和放大控制；
- 文章详情中的主操作统一显示固定文案“重新处理”，按钮宽度固定；长标题、长错误信息或状态数字变化不会改变按钮文字或挤压按钮；未完成记录会根据实际状态显示“处理中”“处理失败”或“已停止”，不再统一误报成旧版本不完整记录；
- 文章详情中的图片优先从本机已校验原图缓存读取，本地缓存不存在时才回退到图床/源图，避免图床网络短暂抖动导致预览缺图；
- CanonicalDocument 与 Markdown 输出；
- 标题、段落、标题层级、列表、引用、代码、表格、链接和图片映射；
- 按 Post 的 `media_key` 隔离图片，避免多篇文章合并响应时串图；
- 原图缓存、SHA-256 去重、远程 URL 验证；
- 写入前执行正文逐块顺序、重复段落、原始换行、媒体 ID、图片/视频数量与顺序、HTTPS 地址、富文本范围和最终 Markdown 全文一致性校验；任一项不一致都不会标记完成；
- 默认使用本地媒体存储：图片按 SHA-256 去重保存到 `media/images/`，视频保存到 `media/videos/`，Markdown 使用从文章目录指向媒体目录的可移动相对路径；
- 保留两种外部图床路径：uPic 使用其当前选中的图床；手工选择“原生 S3 / R2”时，本应用使用 AWS Signature V4 上传，凭证仅保存到 macOS Keychain；
- SQLite 持久保存作者、文章、流水线状态、错误原因和有界处理日志；
- 原子写入、稳定文件名、作者索引和总索引；
- 左下角归档目录可快速切换：先执行 SQLite WAL 检查点，再复制并逐文件校验数据库、Markdown、来源快照和图片缓存，更新数据库中的绝对路径后才启用新目录；旧目录保留，目标冲突时拒绝覆盖；
- 左下角显示当前媒体存储状态，未就绪时点击可直接定位到存储配置；
- 本地体验样例；
- 生成带 Applications 快捷入口的 arm64 DMG 安装包。
- DMG 提供大图标拖拽安装布局，右侧“应用程序”快捷入口可直接完成移动安装。

## 当前验证边界

- 自动化测试使用合成 X API 兼容数据和浏览器采集结构，默认不读取实时 X 数据、不上传第三方文章；
- 最终完整性以 X 页面实际渲染块为准；如果文章页未加载完、Post ID 不匹配、出现未支持块或图片地址无效，应用会拒绝覆盖本地文章；
- 本机没有 Developer ID 签名身份和公证凭证，因此当前 DMG 为本机测试用 ad-hoc 签名；
- 本机已对当前 App Store 版 uPic 1.4.9 的默认图床完成 1×1 合成图与真实 MP4 上传，并由本应用执行 HTTPS 回读验证；
- uPic 模式不读取、复制、回显或记录 uPic 密钥；合成测试图在用户已选择的归档目录内短暂分期，上传结束后自动删除，以同时验证 uPic 能读取后续媒体缓存。

## 首次使用

1. 选择一个本地归档目录。
2. 在受支持的本机浏览器登录 `x.com`，打开 MarkX 设置检查会话读取状态；若 macOS 限制读取，可选择浏览器数据目录授权。现有登录无需重新输入密码。
3. 保持默认的“本地存储”即可直接使用；也可切换为 uPic 或手工配置的原生 S3/R2。
4. 如选外部图床，等待 1×1 测试图的上传和 HTTPS 回读验证通过；本地存储无需此步。
5. 粘贴博主 `@handle` 或主页链接，选择篇数（默认 10 篇）后开始；应用会直接打开该博主的 `/articles` 专属列表获取文章链接，再逐篇等待完整排版稳定、保存图片/视频和 Markdown。也可以一次粘贴 1–500 条 X Article 链接。

> 当前正常下载链路不调用 X API：不会读取博主普通 Post，也不会产生 Post Read、User Read 或 Full-Archive Search 费用。

## 测试

```bash
swift test
```

默认测试覆盖源文件保护、停止任务、中文搜索、缓存整理、浏览器会话隔离与回退、媒体回读、DOM 抽取和目录迁移。真实 X、浏览器、uPic 和视频联调仍需显式启用；默认测试不读取实时会话，不上传用户归档。2026-11-09 实测 166 项：161 项通过、5 项外部联调跳过、0 项失败；另行启用的真实 Chrome 会话读取测试通过，未输出 Cookie 值。

真实端到端验收已用先前失败的《Codex 实战系列｜ 零代码个人网站搭建》完成：应用显示成功 1 篇、失败 0 篇、10 张图片、1 个视频；实际 MP4 为 H.264/AAC、1438×720、27.65 秒、3,134,794 字节。远程 Range 回读返回 HTTP 206、`video/mp4` 和有效 `ftyp` 头，SQLite 记录 `video_count = 1`，Markdown 已写入原位置视频块。从最终 DMG 安装的应用内，系统播放控件识别出 `00:28` 时长，已实际播放到 `27.61` 秒结束，应用进程保持稳定。同一最终安装版在设置页通过 uPic 真实上传与 `1want.link` HTTPS 回读验证。

目录切换会正确跳过任意层级的 `.DS_Store` 和 SQLite 临时文件，不会再误跳过同目录后面的文章或图片；先前失败留下的同源目标资料库也可以安全重试。

文章阅读字号会联动调整行高、段落间距、标题间距、列表项间距、列表缩进、引用和代码区块内边距。旧快照中缺少序号时会自动恢复连续编号；Markdown 有序列表使用实际序号、四空格嵌套缩进和明确的列表结束空行。仅自动升级导出校验值仍有效的 Markdown，不覆盖手工修改。

使用当前 Chrome 配置验证 X 会话导入：

```bash
RUN_CHROME_SESSION_INTEGRATION=1 swift test --filter ChromeXSessionReaderTests/testReadsLiveChromeXSessionWhenExplicitlyEnabled
```

真实 uPic 集成测试：

```bash
RUN_UPIC_INTEGRATION=1 swift test --filter ArchivePipelineTests/testUPicLiveIntegrationWhenExplicitlyEnabled
```

真实 X 渐进式 MP4 下载与文件校验：

```bash
RUN_X_VIDEO_INTEGRATION=1 swift test --filter VideoDownloaderTests/testDownloadsRealXProgressiveMP4WhenExplicitlyEnabled
```

使用当次官方 X API 响应验证全文解析：

```bash
X_ARTICLE_RESPONSE_FIXTURE=/path/to/response.json swift test --filter XContentDecoderTests/testLiveResponseFixtureWhenExplicitlyProvided
```
