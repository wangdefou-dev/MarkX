# X 长文归档器

一个面向 Apple Silicon Mac 的原生 X 长文归档工具。当前版本为研发预览 `0.1.2`（Build 50）。

## 已实现

- SwiftUI 原生三栏资料库界面；
- X 黑白配色的大号完整 X 标志，三条文章横线位于 X 左上斜臂的黑色内镂空中，包含完整 macOS `.icns` 尺寸；
- 首次配置与本地归档目录；
- 自动复用本机 Chrome 的 X 登录态；应用不再提供 X Developer API 配置、Bearer Token 输入或钥匙串读取，升级后会清理旧版保存的 Token；
- 单个博主主页下载和多账号批量输入；
- 支持一次粘贴 1–500 条 X Article `status` 或 `article` 链接，按输入顺序在应用内打开 X 页面并采集；
- 「单个博主」的博主主页输入框严格限制为一行：回车不换行，粘贴多行内容时只保留第一条非空内容；批量博主和文章链接仍使用多行输入；
- 在默认“单个博主”页直接粘贴 `/status/` 或 `/article/` 文章链接时，会自动切换为文章直链模式，不会误将用户名当成博主后扫描 300 条 Post；
- 侧边栏和工具栏使用统一的“开始下载文章”入口，在同一窗口选择单个博主、批量博主或文章链接；
- 左侧资料库的“全部文章”“处理中”“需要处理”始终显示与当前筛选结果一致的数字；每个博主行显示该博主已经完成下载的文章数，包括 0；
- 博主行只负责选择和显示统计，不常驻任何功能按钮；查看主页、重新拉取和删除都从该行右键菜单选择。“全部文章”“处理中”“需要处理”的相关操作也集中到各自右键菜单；
- 博主发现直接打开 `https://x.com/<handle>/articles`，只滚动 Article 专属列表并收集精确 `/status/PostID` 链接，不扫描博主普通 Post；
- 博主发现、直接链接下载、已有文章重新获取和完整正文保存全部为 **0 次 X API 请求**；本地已通过完整性校验的文章默认跳过；
- 最近文章数量可选（1–100 篇），默认每位博主最近 10 篇；
- 选择“完整历史”时自动滚动 Articles 专属列表直至底部，不调用 Full-Archive Search；
- 右上角“立即同步”是独立批量功能：点击后先弹窗确认每位博主要检查的最近 1–100 篇（默认 10 篇），确认后才在后台同步全部已跟踪博主；博主总数不设上限，100 位或更多也会全部进入队列；
- “同步所有博主文章”弹窗重新统一了工具栏与弹窗的同步图标、标题字号、正文字号、图标容器和卡片间距；“立即同步”和“定时同步”通过顶部分段选择分开；
- 支持每日定时后台同步：可选时间和每位博主文章数，保存后注册用户级 macOS LaunchAgent；应用窗口关闭时也能隐藏唤起，睡眠错过后会在下次唤醒时补执行一次，完全关机时无法执行；
- 定时同步会持久保存最近执行时间与结果；上一个任务仍在运行时安全跳过本次，不会并发写入同一资料库；
- 批量同步会自动跳过已经通过完整性校验的本地归档，只让新文章和未完成文章进入正文队列；过程显示检查、保存、跳过、失败与图片/视频数量，结束后显示独立同步结果；
- 输入博主主页后使用纯原生后台进度窗口：逐条显示从 Articles 专属列表识别到的文章标题与精确链接，不展示 X 浏览器页面；
- 发现和正文下载的进度窗口每次打开都以主软件窗口为锚点居中；可点击「隐藏到后台」或红色关闭按钮收起，不会取消 WebKit 页面、当前文章或后续队列；任务运行期间可从主窗口工具栏「显示下载进度」重新打开，并按主窗口最新位置再次居中；
- 正文下载阶段继续隐藏浏览器，只显示每篇文章的等待、下载中、已保存或失败状态；全部结束后统一报告成功、跳过、失败和图片/视频数量；
- 精确采集可随时停止，停止后不再自动进入下一篇，未完成任务保留并可从侧边栏继续；
- “需要处理”的右键菜单支持重新处理全部待处理任务或清空任务；文章行右键菜单支持重新处理单篇和删除单条任务。删除前必须确认；已有 Markdown、全文快照和图片归档保留，只删除未归档临时记录或取消后续重试；
- 所有按钮、图标按钮、菜单入口和分段选择器都提供鼠标悬停说明，提示会执行的动作及删除边界；
- 任务进度明确显示 `X API 0`、已发现文章、已保存文章和已保存图片/视频；
- “全部文章”按发布时间平铺展示，不再按作者分段；本地文件仍按博主目录归档；
- 文章支持右键删除并在确认后移入 macOS 废纸篓，同时清理数据库记录、来源快照和索引；远程图床文件不会被误删；
- 已存在的博主可从侧边栏反复“重新拉取文章”，每次都能重新选择 1–100 篇或完整历史；
- 博主行保持简洁，不显示刷新和删除图标；右键菜单保留查看主页、重新拉取和删除博主。删除只停止跟踪，已下载文章、本地媒体缓存和远程图片/视频都会保留，再次添加即可恢复拉取；
- 选中博主后，窗口最顶部的导航区只保留一行“博主名称 + 查看主页”，按钮紧跟博主名称右侧；文章列表只保留文章卡片；
- 最近范围和完整历史模式；
- 严格只识别带官方 `article` 字段的 X Article；Note Post、普通 Post 和自回复线程不计数、不下载；
- 内置不可见的非持久化 X Article 页面运行时，仅从 `twitterArticleReadView` / `longformRichTextComponent` 读取已渲染的文章块；采集时不会把 X 页面界面展示给用户；
- 每篇文章默认自动读取 Chrome 当前配置的 X 登录状态，等待页面排版连续稳定后自动保存，不再要求重复输入 X 密码或手动点击保存；
- Chrome 会话只在本机内存中用于当前后台采集，仅解密 `x.com` / `twitter.com` 必需 Cookie，不读取 Google 或其他网站，不打印、不落盘、不上传给开发者；失败原因会收进最终结果，不要求在网页窗口中手动处理；
- 按 X 页面原始顺序采集封面、标题层级、段落、有序/无序列表、引用、表格、粗体/斜体/删除线/下划线、链接、代码块和内文图片；未知块出现时拒绝导出，不猜测位置；
- 正文中的“引用其他 X Article”卡片在原位置简化为唯一的引用文章链接；不会把卡片作者、日期、摘要和互动数据误当正文，也不会误存作者主页；
- uPic 模式直接调用 uPic 上传本地缓存的图片和 MP4，不读取、复制或记录 uPic 容器中的图床配置与密钥；返回 URL 后由本应用通过 HTTPS Range 回读验证；
- 只把 `pbs.twimg.com/media/` 下的真实 Article 媒体视为正文图片，排除头像、emoji 和页面图标；保存前校验所有图片已加载且媒体 ID 数量齐全；
- X 原图下载、S3/R2 上传和上传后公网回读均有有界自动重试；同一篇文章反复失败只计为 1 篇，成功后自动清除失败状态；
- 兼容 X Article 正文内视频：从页面媒体元数据选择最高分辨率渐进式 MP4，排除 `blob:`、HLS、音轨和初始化分片；
- MP4 下载后校验 MIME、文件头、大小与 SHA-256，默认保存到归档目录 `media/videos/`；选择 uPic 或 S3/R2 时则上传并回读验证；
- 视频保留原文块顺序：Markdown 输出 HTML5 `<video controls>` 和备用下载链接，App 详情页用 AppKit `AVPlayerView` 直接播放已验证 MP4；解析、下载、上传或回读失败时不伪装完成；
- 音频、直播、只有 HLS 的媒体和外站 iframe 暂不在本次视频兼容范围内；
- 忽略 X DraftJS 遗留的零高度空原子节点：只有节点同时无子元素、无文字、无媒体身份且不占据任何页面高度时才安全跳过；真实未知块和仍占位的懒加载内容继续严格拒绝，避免把残缺正文误标为完成；
- 右侧以文章阅读版式展示已校验的完整正文、富文本样式、代码和全部图片，并提供 80%–160% 的文字缩小、恢复和放大控制；
- 文章详情和旧归档提示中的主操作统一显示固定文案“重新处理”，按钮宽度固定；长标题、长错误信息或状态数字变化不会改变按钮文字或挤压按钮；
- 文章详情中的图片优先从本机已校验原图缓存读取，本地缓存不存在时才回退到图床/源图，避免图床网络短暂抖动导致预览缺图；
- CanonicalDocument 与 Markdown 输出；
- 标题、段落、标题层级、列表、引用、代码、表格、链接和图片映射；
- 按 Post 的 `media_key` 隔离图片，避免多篇文章合并响应时串图；
- 原图缓存、SHA-256 去重、远程 URL 验证；
- 写入前执行正文逐块顺序、重复段落、原始换行、媒体 ID、图片/视频数量与顺序、HTTPS 地址、富文本范围和最终 Markdown 全文一致性校验；任一项不一致都不会标记完成；
- 默认使用本地媒体存储：图片按 SHA-256 去重保存到 `media/images/`，视频保存到 `media/videos/`，Markdown 使用从文章目录指向媒体目录的可移动相对路径；
- 保留两种外部图床路径：uPic 使用其当前选中的图床；手工选择“原生 S3 / R2”时，本应用使用 AWS Signature V4 上传，凭证仅保存到 macOS Keychain；
- SQLite 作者、文章和流水线状态；
- 原子写入、稳定文件名、作者索引和总索引；
- 左下角归档目录可快速切换：先执行 SQLite WAL 检查点，再复制并逐文件校验数据库、Markdown、来源快照和图片缓存，更新数据库中的绝对路径后才启用新目录；旧目录保留，目标冲突时拒绝覆盖；
- 左下角显示当前媒体存储状态，未就绪时点击可直接定位到存储配置；
- 本地体验样例；
- arm64 `.app`、ZIP 和 DMG 打包。
- DMG 提供大图标拖拽安装布局，右侧“应用程序”快捷入口可直接完成移动安装。

## 当前验证边界

- 自动化测试使用合成 X API 兼容数据和浏览器采集结构，默认不读取实时 X 数据、不上传第三方文章；
- 最终完整性以 X 页面实际渲染块为准；如果文章页未加载完、Post ID 不匹配、出现未支持块或图片地址无效，应用会拒绝覆盖本地文章；
- 本机没有 Developer ID 签名身份和公证凭证，因此当前 DMG 为本机测试用 ad-hoc 签名；
- 本机已对当前 App Store 版 uPic 1.4.9 的默认图床完成 1×1 合成图与真实 MP4 上传，并由本应用执行 HTTPS 回读验证；
- uPic 模式不读取、复制、回显或记录 uPic 密钥；合成测试图在用户已选择的归档目录内短暂分期，上传结束后自动删除，以同时验证 uPic 能读取后续媒体缓存。

## 首次使用

1. 选择一个本地归档目录。
2. 先在本机 Chrome 登录 `x.com`；应用会自动复制当前登录态到临时采集窗口，无需重复输入密码。
3. 保持默认的“本地存储”即可直接使用；也可切换为 uPic 或手工配置的原生 S3/R2。
4. 如选外部图床，等待 1×1 测试图的上传和 HTTPS 回读验证通过；本地存储无需此步。
5. 粘贴博主 `@handle` 或主页链接，选择篇数（默认 10 篇）后开始；应用会直接打开该博主的 `/articles` 专属列表获取文章链接，再逐篇等待完整排版稳定、保存图片/视频和 Markdown。也可以一次粘贴 1–500 条 X Article 链接。

> 当前正常下载链路不调用 X API：不会读取博主普通 Post，也不会产生 Post Read、User Read 或 Full-Archive Search 费用。

## 测试

```bash
swift test
```

截至 2026-09-05，本地实际运行共 70 项默认测试：65 项通过、5 项显式外部联调测试跳过、0 项失败。统计测试覆盖三个资料库筛选数字与博主已完成下载数；本地媒体端到端测试同时校验图片、MP4、SHA-256 落盘、快照相对 URL 和 Markdown 可移动路径；单个博主输入测试覆盖回车、CRLF、Unicode 换行和编辑中的普通单行文本。默认测试不读取实时 X/Chrome 会话数据，也不写入外部 S3/R2；Chrome 会话联调只校验存在性、数量和域名范围，不输出 Cookie 值。

真实端到端验收已用先前失败的《Codex 实战系列｜ 零代码个人网站搭建》完成：应用显示成功 1 篇、失败 0 篇、10 张图片、1 个视频；实际 MP4 为 H.264/AAC、1438×720、27.65 秒、3,134,794 字节。远程 Range 回读返回 HTTP 206、`video/mp4` 和有效 `ftyp` 头，SQLite 记录 `video_count = 1`，Markdown 已写入原位置视频块。从最终 ZIP 安装的应用内，系统播放控件识别出 `00:28` 时长，已实际播放到 `27.61` 秒结束，应用进程保持稳定。同一最终安装版在设置页通过 uPic 真实上传与 `1want.link` HTTPS 回读验证。

目录切换会正确跳过任意层级的 `.DS_Store` 和 SQLite 临时文件，不会再误跳过同目录后面的文章或图片；先前失败留下的同源目标资料库也可以安全重试。

文章阅读字号会联动调整行高、段落间距、标题间距、列表项间距、列表缩进、引用和代码区块内边距。旧快照中缺少序号时会自动恢复连续编号；Markdown 有序列表使用实际序号、四空格嵌套缩进和明确的列表结束空行。仅自动升级导出校验值仍有效的 Markdown，不覆盖手工修改。

使用当前 Chrome 配置验证 X 会话导入：

```bash
RUN_CHROME_SESSION_INTEGRATION=1 swift test --filter ChromeXSessionReaderTests/testReadsLiveChromeXSessionWhenExplicitlyEnabled
```

真实 uPic 集成测试：

```bash
RUN_UPIC_INTEGRATION=1 swift test --filter ArchivePipelineTests/testUPicLiveIntegrationWhenExplicitlyEnabled
```

真实 X 渐进式 MP4 下载与文件校验：

```bash
RUN_X_VIDEO_INTEGRATION=1 swift test --filter VideoDownloaderTests/testDownloadsRealXProgressiveMP4WhenExplicitlyEnabled
```

使用当次官方 X API 响应验证全文解析：

```bash
X_ARTICLE_RESPONSE_FIXTURE=/path/to/response.json swift test --filter XContentDecoderTests/testLiveResponseFixtureWhenExplicitlyProvided
```

仅研发者显式传入环境变量时，可运行旧响应解析的隔离联调（产品应用不保存或读取 Token）：

```bash
RUN_X_DIRECT_INTEGRATION=1 X_API_BEARER_TOKEN=... swift test --filter XAPIClientDirectArticleTests/testLiveDirectArticleLookupWhenExplicitlyEnabled
```
